# iqdb v0.5.0 — Family Composition + Approximate Indices

**iQDB is now the database that ties the iqdb crate family together.** v0.5.0 re-platforms the crate from a self-contained implementation onto its published siblings: it composes `iqdb-types` for the shared vocabulary, `iqdb-index` for the search seam, `iqdb-flat` / `iqdb-hnsw` / `iqdb-ivf` for exact and approximate search, `iqdb-persist` for durable storage, and `iqdb-cache` for an optional result cache. A database now fixes its dimensionality and distance metric at open time and routes queries through a selectable index. This is a breaking change from the 0.4.x surface; the crate is pre-1.0, so the break is permitted under SemVer.

## What is iqdb?

An embedded vector database for Rust — a single-process, in-application similarity-search engine for high-dimensional workloads where every microsecond on the query path matters. It targets the operational shape of `sqlite` or `redb`: no daemon, no network hop, no separate runtime. Open a handle, write vectors, query nearest neighbours — all from inside your binary.

## What's new in 0.5.0

### The crate now composes the family

Through 0.4.0, `iqdb` carried its own `Vector`, `RecordId`, `Record`, `Payload`, `DistanceMetric`, search kernel, and persistence. The family crates were specced as the portable substrate for the same surface (and for the future distributed product line), so the standalone crate duplicated a subset of them. v0.5.0 resolves the DIRECTIVES §9 decision gate in favour of composition: `iqdb` depends on the published 1.0 family and exposes its vocabulary directly.

The vector vocabulary is re-exported from `iqdb-types`:

```rust
use iqdb::{DistanceMetric, Filter, Hit, Metadata, Value, Vector, VectorId};
```

### `dim` and `metric` are fixed at construction

An HNSW graph and an IVF clustering are both built around a specific dimensionality and metric — neither can change without a rebuild — so a database now declares both up front:

```rust
use iqdb::{DistanceMetric, Iqdb, Result, Vector, VectorId};

fn run() -> Result<()> {
    let db = Iqdb::open_in_memory(3, DistanceMetric::Cosine)?;
    db.upsert(VectorId::from(1u64), Vector::new(vec![1.0, 0.0, 0.0])?, None)?;

    // No metric argument — the database metric is used.
    let hits = db.search(&Vector::new(vec![1.0, 0.0, 0.0])?, 1)?;
    assert_eq!(hits[0].id, VectorId::from(1u64));
    Ok(())
}
# run().unwrap();
```

A welcome consequence: a wrong-dimension vector is now rejected at `upsert` (boundary validation) instead of surfacing at search time.

### Selectable index — Flat, HNSW, IVF

`Iqdb::open_in_memory` / `open` default to the exact flat index. To pick an approximate index, pass an `IqdbConfig` to the `_with` constructors. The config is fluent, mirroring `iqdb-cache`'s own `CacheConfig`, and per-index tuning lives inside the `IndexKind` variants:

```rust
use iqdb::{CacheConfig, DistanceMetric, HnswConfig, IndexKind, Iqdb, IqdbConfig};

# fn run() -> iqdb::Result<()> {
let cfg = IqdbConfig::new(128, DistanceMetric::Cosine)
    .index(IndexKind::Hnsw(HnswConfig::default().with_ef_search(96)))
    .cache(CacheConfig::new().capacity(10_000));
let db = Iqdb::open_in_memory_with(cfg)?;
# assert!(db.is_empty());
# Ok(())
# }
# run().unwrap();
```

Flat is the recall ground truth the approximate indices are measured against. HNSW accepts incremental inserts directly. IVF requires training: `iqdb` accumulates vectors in its authoritative store and trains the IVF index lazily from them on the first search; `Iqdb::optimize` retrains the centroids after many writes.

### Durable storage via `iqdb-persist`

The hand-rolled snapshot + WAL of 0.4.0 is replaced by `iqdb-persist`. Because the family indices cannot be serialized through the `IndexCore` trait (their state is private and the trait exposes no vector iteration), `iqdb` owns an authoritative row store, serializes *that*, and rebuilds the derived index on load. The result is the same durability contract — atomic snapshot, write-ahead log, CRC32-checked frames, corrupt-tail recovery — now with optional `zstd` / `lz4` snapshot compression.

```rust,no_run
use iqdb::{DistanceMetric, Iqdb, Result, Vector, VectorId};

fn run() -> Result<()> {
    let db = Iqdb::open("./data/vectors.iqdb", 3, DistanceMetric::Cosine)?;
    db.upsert(VectorId::from(1u64), Vector::new(vec![0.1, 0.2, 0.3])?, None)?;
    db.flush()?;
    db.close()
}
# run().unwrap();
```

`len()` reads the authoritative store, so it is correct regardless of whether the derived index has been materialized — which is what keeps the persistence layer's `len == header.n_vectors` reload check satisfied even for a not-yet-trained IVF.

### Optional result cache and `optimize`

`IqdbConfig::cache` wraps searches in an `iqdb-cache` result cache (invalidated on every mutation, so never stale); `Iqdb::cache_stats` reports hits and misses. `Iqdb::optimize` rebuilds the approximate index over the current vectors.

## Breaking changes

The public surface is rebuilt on the family vocabulary. The notable breaks:

- **Constructors take `(dim, metric)`** (or an `IqdbConfig`), and `open_in_memory` / `open_in_memory_with` now return `Result<Self>` (construction validates `dim` and the index configuration rather than panicking).
- **`search(&query, k)` drops its `metric` argument** — the metric is fixed at open.
- **`upsert(id, vector, metadata)`** replaces `upsert(record)`; **`get` returns `(Vector, Option<Metadata>)`**; **`search` returns `Vec<Hit>`** instead of `Vec<SearchResult>`.
- **Filters are declarative `Filter` expressions**, not closures.
- **`open(path, dim, metric)` treats `path` as the snapshot file** (the WAL lives beside it), replacing the directory layout. A reopen with a mismatched `dim` / `metric` fails with `Error::Config`.
- **`Error` becomes `Index(IqdbError)` / `Persist(PersistError)` / `Config(&'static str)`**, wrapping the family error vocabularies.
- **`DistanceMetric` is `Cosine` / `DotProduct` / `Euclidean` / `Manhattan` / `Hamming`** — the old `L2` is `Euclidean`, `Dot` is `DotProduct`.
- The self-contained `Record` / `RecordId` / `Payload` / `PayloadValue` / `SearchResult` types, the in-crate codec / file-store / platform modules, and the `libc` dependency are removed.

Run on Windows x86_64 and on WSL2 Ubuntu (Rust stable); the same commands run in the configured CI matrix on Linux, macOS, and Windows:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings

cargo test
cargo test --all-features
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
cargo +1.87 build
```

All green. Test counts at this tag (`--all-features`): 34 unit + 10 persistence + 2 property + 3 recall integration + 17 doctests. Recall is validated against the exact flat oracle: HNSW clears recall@10 ≥ 0.9 and IVF (probing all clusters) ≥ 0.95 on the synthetic gate.

## What's next

- **v0.6.0 — async surface.** A Tokio-driven async mirror of the public API, cancellation-safe, with the durable write path offloaded via `spawn_blocking`. The default (sync) build is unaffected.
- **v1.0.0 — stable.** API and on-disk format frozen, full benchmark suite, migration guide from 0.x.
