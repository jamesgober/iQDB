# iqdb v0.8.0 — Decoder Hardening (beta)

**The on-disk decoder is now safe against hostile input.** v0.8.0 is a beta-hardening release: it bounds every allocation the frame decoder makes, adds fuzz-style coverage proving a malformed frame never panics or over-allocates, and records that the supply-chain gates pass. There are no API changes.

## What is iqdb?

An embedded vector database for Rust: exact and approximate similarity search, declarative filters, durable storage with tunable fsync and compression, an optional result cache, and an opt-in async surface — the integration layer over the iqdb crate family, all behind one small handle.

## What's new in 0.8.0

### Bounded decoding — no OOM on a crafted payload

The on-disk payload is self-describing: it carries length fields for the row count, each vector's dimensionality, byte-key ids, metadata entry counts, and strings. Those fields are untrusted. The previous decoder sized buffers directly from them — `vec![0f32; dim]`, `Vec::with_capacity(n_rows)`, `vec![0u8; len]` — so a corrupt or maliciously crafted payload naming a multi-gigabyte length could trigger an out-of-memory abort before a single byte of the body was validated.

v0.8.0 closes that. Capacity hints are clamped to a small bound (`MAX_PREALLOC`), and every length-driven collection grows only as real bytes arrive. A length larger than the data on the wire now fails fast with `PersistError::TruncatedPayload`:

- the per-row vector buffer grows by `push` as components are read, instead of `vec![0f32; dim]`;
- the row vector and metadata-entry vectors clamp their initial capacity;
- byte buffers read through `Read::take(len).read_to_end`, which never pre-allocates more than is present.

This upholds the engineering rule that every allocation is bounded and library code never panics on hostile input. In normal operation the `iqdb-persist` CRC32 already rejects corruption before the payload is decoded; this change makes the decoder sound on its own, in depth.

### Fuzz-style robustness coverage

The decoder is the on-disk frame parser the directives single out for fuzzing. v0.8.0 adds the stable, in-CI equivalent — property tests in `src/engine/codec.rs` that assert the decoder is panic- and OOM-free across:

- arbitrary byte sequences;
- arbitrary input behind a valid magic + version header (so the decoder proceeds into the length-driven body);
- every single-bit flip of a valid payload;
- every truncated prefix of a valid payload (each is rejected; the full payload still decodes).

### Supply-chain gates verified

`cargo deny check` (advisories, bans, licenses, sources) and `cargo audit` both pass — 0 advisories across the 118-crate dependency tree — satisfying the dependency-policy item of the Definition of Done.

## Breaking changes

**None.** This release changes only the decoder's internal allocation strategy and adds tests. The on-disk format, the public API, and all behaviour on valid input are unchanged.

## Verification

Run on Windows x86_64 and on WSL2 Ubuntu (Rust stable); the same commands run in the configured CI matrix on Linux, macOS, and Windows:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test
cargo test --all-features
cargo deny check
cargo audit
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
cargo +1.87 build --all-features
```

All green. Test counts with `--all-features`: 42 unit (incl. the new decoder-robustness properties) + 3 async + 12 persistence + 2 property + 3 recall + 21 doctests.
