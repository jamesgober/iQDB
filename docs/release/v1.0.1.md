# iqdb v1.0.1

A fix release. No API or on-disk format changes. It raises the floors on the
crates it builds on to their fixed releases.

## Fixed

- **Writes after a crash recovery survive the next restart.** If a crash
  tore the last frame of the write-ahead log, the next open recovered
  correctly, but every write acknowledged after that was lost on the
  following restart. `iqdb-persist` 1.0.1 cuts the torn bytes off before
  appending.
- **HNSW search after deletes and updates.** A query whose neighbourhood had
  been deleted or replaced could come back empty while live rows remained.
  `iqdb-hnsw` 1.1.0 no longer lets deleted nodes crowd out live ones.
- **HNSW memory under updates.** Each update of an existing id left its old
  graph node behind, so memory grew with the number of writes. The graph is
  now rebuilt from the live rows once deleted nodes outnumber them (and
  number at least 1,024), and `Iqdb::optimize` rebuilds it on demand.
- **Small IVF databases answer searches.** An IVF database needs
  `n_clusters` rows (256 by default) to train. Below that, every search used
  to fail with `InvalidConfig` after taking the write lock. Searches now scan
  every row exactly until there are enough rows, and the index trains on the
  first search after that.
- **README accuracy.** The README promised a lock-free hot path, an
  allocation-free steady state, and a cache-aware on-disk layout. It now says
  what the code does: searches share a read lock, and every write is logged
  and `fsync`ed before it is acknowledged. It also notes that a database file
  should be opened from one handle in one process at a time.

## Security

- **`k` is bounded.** `search` clamps `k` to the number of stored rows, so a
  huge `k` from a request can no longer reach an index allocation and abort
  the process.
- **Stored index sizes are bounded.** A snapshot whose stored HNSW `m` or IVF
  `n_clusters` is impossibly large now fails to load with an error instead of
  aborting the process.
- **Bounded decompression and filters** come with `iqdb-persist` 1.0.1 and
  `iqdb-filter` 1.1.0.

## Upgrading

Change the version to `1.0.1`. Nothing else is needed.
