# iqdb v0.1.0 — Scaffolding

**The first published surface.** v0.1.0 establishes the public crate boundary, the lifecycle handle (`open` / `open_in_memory` / `flush` / `close`), the unified [`Error`] / [`Result`] types, and the strict REPS lint profile. CI is green on Linux, macOS, and Windows. The query verbs (`upsert`, `search`, `delete`) land in subsequent milestones — every method on the engine path that has no implementation yet returns `Error::NotImplemented` so call sites can be wired ahead of the real engine arriving.

## What is iqdb?

An embedded vector database for Rust — a single-process, in-application similarity-search engine designed for high-dimensional workloads where every microsecond on the query path matters. It targets the same operational shape as `sqlite` or `redb`: no daemon, no network hop, no separate runtime. Open a handle, write vectors, query nearest neighbours — all from inside your binary. The engine is being built against a lock-free hot path, an allocation-free steady state, and a cache-aware on-disk layout, with pluggable indices and pluggable storage so workloads can trade recall for latency without rewriting the surrounding application.

## What's new in 0.1.0

### Public lifecycle handle — `Iqdb`

The top-level [`Iqdb`] handle is the entry point every consumer reaches for. v0.1.0 ships four methods:

- `Iqdb::open(path)` — open or create a file-backed database. Returns `Error::NotImplemented` in this release; lights up in v0.4.0 (durable storage).
- `Iqdb::open_in_memory()` — open an ephemeral, in-memory instance. Wired through; never touches the filesystem.
- `Iqdb::flush()` — flush pending writes to durable storage. Returns `Error::NotImplemented` until the durable backend lands in v0.4.0.
- `Iqdb::close(self)` — consume the handle and release all held resources.

```rust
use iqdb::{Iqdb, Result};

fn main() -> Result<()> {
    let db = Iqdb::open_in_memory();
    db.close()?;
    Ok(())
}
```

The staged-surface pattern below lets downstream callers wire `Iqdb::flush` and `Iqdb::open(path)` now, then get real behaviour automatically when v0.4.0 ships — no API churn required:

```rust
use iqdb::{Error, Iqdb, Result};

fn flush_if_supported(db: &Iqdb) -> Result<()> {
    match db.flush() {
        Ok(()) => Ok(()),
        Err(Error::NotImplemented) => Ok(()),
        Err(err) => Err(err),
    }
}
```

### Unified error type — `Error` / `Result<T>`

A single `#[non_exhaustive]` enum covers every fallible operation in the crate. v0.1.0 ships three variants:

- `Error::Io(std::io::Error)` — a lower-level I/O failure. Wraps `std::io::Error` so callers can inspect `ErrorKind` and decide retry / fallback / surface-to-user.
- `Error::InvalidConfig(&'static str)` — runtime configuration error at open time. Programmer error — fix the construction site.
- `Error::NotImplemented` — the requested operation belongs to a later milestone and has no engine behind it yet.

The error type implements `std::error::Error` and has a `From<std::io::Error>` conversion so the `?` operator threads I/O errors through naturally. The `io_error_display_does_not_leak_payload` test asserts the `Display` impl redacts the inner message (only `ErrorKind` is printed) — REPS Security mandate, enforced from day one.

```rust
use iqdb::{Error, Result};

fn classify(err: Error) -> &'static str {
    match err {
        Error::Io(_) => "io",
        Error::InvalidConfig(_) => "config",
        Error::NotImplemented => "stub",
        _ => "unknown",
    }
}

# fn check() -> Result<()> { Ok(()) }
```

The trailing `_` arm is required because `Error` is `#[non_exhaustive]` — new variants will appear in minor releases without a SemVer break.

### Strict REPS lint profile

The crate root in [`src/lib.rs`](../../src/lib.rs) enables the full Rust Efficiency & Performance Standards lint set:

```rust
#![deny(warnings)]
#![deny(missing_docs)]
#![deny(unsafe_op_in_unsafe_fn)]
#![deny(unused_must_use)]
#![deny(unused_results)]
#![deny(clippy::unwrap_used)]
#![deny(clippy::expect_used)]
#![deny(clippy::todo)]
#![deny(clippy::unimplemented)]
#![deny(clippy::print_stdout)]
#![deny(clippy::print_stderr)]
#![deny(clippy::dbg_macro)]
#![deny(clippy::unreachable)]
#![deny(clippy::undocumented_unsafe_blocks)]
```

Test modules locally relax `clippy::unwrap_used` / `clippy::expect_used` / `clippy::print_stdout` / `clippy::print_stderr` so assertion scaffolding stays ergonomic — the strict profile is for production library code, not test fixtures. The relaxation is scoped to `#[cfg(test)]` blocks; production paths cannot reach for `unwrap()` to silence an error.

### Cross-platform CI matrix

[`.github/workflows/ci.yml`](../../.github/workflows/ci.yml) runs six jobs on every push / PR:

- **`build-test`** — `cargo build` + `cargo test` across the `ubuntu-latest` × `macos-latest` × `windows-latest` matrix. `fail-fast: false` so a flake on one platform does not mask progress on the others.
- **`msrv`** — `cargo build` against Rust 1.87 on Ubuntu, proving the crate honours its declared minimum supported toolchain.
- **`lint`** — `cargo fmt --all -- --check` and `cargo clippy --all-targets -- -D warnings`.
- **`docs`** — `RUSTDOCFLAGS=-D warnings cargo doc --no-deps` — every `///` comment must hold up to rustdoc's strict gate.
- **`audit`** — `cargo audit --deny warnings` against the RustSec advisory database. Pinned to `cargo-audit ^0.22` because earlier versions reject CVSS 4.0 entries.
- **`deny`** — `cargo deny check` runs the advisories / bans / licenses / sources gates against [`deny.toml`](../../deny.toml).

### Dependency-policy gate — `deny.toml`

The license policy permits the MIT / Apache-2.0 family plus the standard permissive licenses (`BSD-3-Clause`, `BSD-2-Clause`, `ISC`, `CC0-1.0`, `MIT-0`, `MPL-2.0`, `Unicode-3.0`, `Unicode-DFS-2016`, `Zlib`). Copyleft (`GPL-*`, `AGPL-*`, `LGPL-*`) is denied. Wildcard version requirements are rejected to prevent silent dependency-tree drift; yanked crates are surfaced as warnings; duplicate major versions are flagged so cargo's resolver cannot silently bundle two copies of a transitive dependency.

### Release-profile tuning

`Cargo.toml` ships an aggressive release profile aimed at the embedded-DB hot path:

```toml
[profile.release]
opt-level = 3
lto = "fat"
codegen-units = 1
panic = "abort"
strip = "symbols"

[profile.bench]
opt-level = 3
lto = "fat"
codegen-units = 1
```

`panic = "abort"` removes unwinding tables from the release binary; `lto = "fat"` lets the linker inline across crate boundaries; `codegen-units = 1` maximises the optimiser's view of the crate at the cost of build wall-time. The bench profile mirrors release optimisation but keeps unwinding so Criterion's panic-on-failure assertions still report cleanly.

### Documentation

Crate-level `///` documentation includes two runnable examples — the in-memory lifecycle and the staged-surface error pattern — both of which are executed by `cargo test --doc` on every CI build. Every public type, method, and error variant carries a doc comment per the REPS Documentation mandate; `#![deny(missing_docs)]` is enforced at the crate root.

## What's next

- **v0.2.0 — Vector primitives.** `Vector`, `DistanceMetric` (Cosine, L2, Dot), `Payload`, `RecordId`. Exact (flat) index. `upsert(id, vec)` / `get(id)` / `delete(id)` against an in-memory store. Optional `serde` feature for vector and payload serialization.
- **v0.3.0 — Search.** `search(query, k)` over the flat index. Batch search. Filter-by-payload predicates. Result ranking with score + id.
- **v0.4.0 — Durable storage.** File-backed storage substrate, write-ahead log, atomic-replace snapshots, crash recovery. `Iqdb::open(path)` becomes load-bearing and the `Error::NotImplemented` branches on `open` / `flush` disappear.
